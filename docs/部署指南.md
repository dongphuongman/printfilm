# Printfilm 部署指南

本文说明 Printfilm（仓库 `ai-manju`）的本地中间件、全栈 Docker、生产 Nginx + HTTPS，以及 ACR 镜像拉取/更新方式。产品操作与 SOP 见 [docs/README.md](./README.md)。

## 1. 架构与端口

| Web | `printfilm-web` | **7050** | Next.js；生产绑 `127.0.0.1` |
| API | `printfilm-api` | **7051** | Spring Boot；生产绑 `127.0.0.1` |

## 3. Compose 文件怎么选

| 文件 | 用途 |
|------|------|
| `docker-compose.yml` | **仅** Postgres + Redis，给本机 `mvn` / `npm run dev` 用 |
| `docker-compose.full.yml` | 全栈（Postgres + Redis + API + Web），端口对外 `7050/7051`，适合内网/联调 |
| `docker-compose.prod.yml` | 生产：Web/API 绑 `127.0.0.1`；**Postgres `7052`、Redis `7053` 对宿主机网卡开放**；Nginx 终结 HTTPS |

业务镜像（ACR）：

| 服务 | 镜像 |
|------|------|
| API | `gcc-registry.cn-hangzhou.cr.aliyuncs.com/gcc/ai-manju-api:latest` |
| Web | `gcc-registry.cn-hangzhou.cr.aliyuncs.com/gcc/ai-manju-web:latest` |

推送记录见 [`.docker/镜像推送记录.md`](../.docker/镜像推送记录.md)。发布参数见 [`.docker-publish.yml`](../.docker-publish.yml)。

## 4. 本地开发：只起数据库

```bash
cd /path/to/ai-manju
docker compose up -d
# 或
npm run docker:up
```

本机再启前后端：

```bash
npm run start:all
# 或分别：npm run api:dev / npm run dev
```

- Web：http://localhost:7050  
- API：http://localhost:7051  

本地前端 API 地址示例：`NEXT_PUBLIC_API_URL=http://localhost:7051`（见 `apps/web/.env.local.example`）。

## 5. 全栈部署（`docker-compose.full.yml`）

适用：服务器直接暴露 7050/7051，或不经过本仓库 Nginx 配置。

```bash
git clone -b main https://www.gitcc.com/yi-ee/ai-manju.git
cd ai-manju

export JWT_SECRET=your-production-jwt-secret-at-least-32-chars
export TOKENFREE_API_KEY=sk-your-tokenfree-key
export ARK_API_KEY=your-ark-seedance-key
export API_BASE_URL=http://服务器IP或域名:7051
export IMAGE_TAG=latest

docker compose -f docker-compose.full.yml pull
docker compose -f docker-compose.full.yml up -d
docker compose -f docker-compose.full.yml ps
```

访问：

- 前端：`http://服务器:7050`
- API：`http://服务器:7051/api/v1/health`

> `full` 中 `api`/`web` 已指向 ACR；本地仍保留 `build:`，可改代码后本地构建再推送。

### 5.1 本地构建（可选）

```bash
docker compose -f docker-compose.full.yml build api web
docker compose -f docker-compose.full.yml up -d
```

构建 Web 时可传 `NEXT_PUBLIC_API_URL`；**运行时**更优先用容器环境变量 `API_BASE_URL`（见 `apps/web/docker-entrypoint.sh`，写入 `runtime-env.js`，改后 `restart web` 即可，无需重建镜像）。

## 6. 生产部署（Nginx + HTTPS）

推荐路径：`docker-compose.prod.yml` + 宿主机 Nginx。

| 文件 | 说明 |
|------|------|
| `docker-compose.prod.yml` | Postgres + Redis + API + Web；API/Web → `127.0.0.1:7051/7050`；**DB/Redis → `0.0.0.0:7052/7053`** |
| `deploy/nginx/printfilm.conf` | `/` → Web，`/api/v1/` → API（含 SSE 长超时），可选 `/gif/` |
| `.env.prod.example` | 生产环境变量模板 |

### 6.1 准备环境变量

```bash
# 建议部署目录示例
cd /opt/ai-manju
cp .env.prod.example .env.prod
```

必改项（模板字段）：

| 变量 | 说明 |
|------|------|
| `POSTGRES_PASSWORD` | 数据库密码 |
| `JWT_SECRET` | JWT 签名密钥（建议 ≥32 字符） |
| `TOKENFREE_API_KEY` | TokenFree（文本/图像）服务端回退 Key |
| `ARK_API_KEY` | 火山方舟 Seedance（视频）Key |
| `IMAGE_TAG` | 镜像标签，默认 `latest` |
| `API_BASE_URL` | **生产建议留空**，浏览器走同源 `/api/v1`（由 Nginx 反代） |
| `CORS_ALLOWED_ORIGINS` | 若跨域访问 API，需包含前端 Origin |

填写后以服务器 `/opt/ai-manju/.env.prod` 为准；完整默认值见上文「线上服务器信息」与 `scripts/deploy_remote.py`。

### 6.2 启动容器

```bash
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
docker compose -f docker-compose.prod.yml ps
```

确认本机环回可通：

```bash
curl -sS http://127.0.0.1:7051/api/v1/health
curl -sS -o /dev/null -w "%{http_code}\n" http://127.0.0.1:7050
```

### 6.2.1 线上数据库 / Redis 端口

`docker-compose.prod.yml` 已开放：

| 服务 | 宿主机端口 | 容器端口 | 连接示例 |
|------|------------|----------|----------|
| PostgreSQL | **7052** | 5432 | `psql -h 47.89.247.240 -p 7052 -U printfilm -d printfilm` |
| Redis | **7053** | 6379 | `redis-cli -h 47.89.247.240 -p 7053` |

密码：`printfilm_dev`（与 `.env.prod` 的 `POSTGRES_PASSWORD`、API 的 `SPRING_DATASOURCE_PASSWORD` 一致）。

**安全建议：**

- 生产务必设置强 `POSTGRES_PASSWORD`，勿使用默认 `printfilm_dev`
- 用云安全组 / 防火墙仅放行运维出口 IP 访问 `7052`、`7053`，勿对全网 `0.0.0.0/0` 裸放
- 若只需本机脚本访问，可改为 `127.0.0.1:7052:5432` / `127.0.0.1:7053:6379` 后 `compose up -d`

### 6.3 安装 Nginx

将仓库内配置装到宿主机（路径以发行版为准）：

```bash
sudo cp deploy/nginx/printfilm.conf /etc/nginx/sites-available/printfilm.conf
sudo ln -sf /etc/nginx/sites-available/printfilm.conf /etc/nginx/sites-enabled/printfilm.conf
```

证书路径（配置内约定）：

- `/etc/letsencrypt/live/www.printfilm.com/fullchain.pem`
- `/etc/letsencrypt/live/www.printfilm.com/privkey.pem`

可用 certbot 签发后：

```bash
sudo nginx -t && sudo systemctl reload nginx
```

反代要点（与 `printfilm.conf` 一致）：

- `location /api/v1/` → `127.0.0.1:7051`，`proxy_buffering off`，读写超时约 3600s（适配 SSE）
- `location /`、`/_next/` → `127.0.0.1:7050`
- `client_max_body_size 110m`

生产媒体公网基址在 `docker-compose.prod.yml` 中默认指向：

- `https://www.printfilm.com/api/v1/media`
- `https://www.printfilm.com/api/v1/uploads`

### 6.4 更新版本

```bash
cd /opt/ai-manju
# 按需改 .env.prod 中 IMAGE_TAG
```

## 11. 排障

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 前端调不通 API | `API_BASE_URL` 或 Nginx 未反代 | 生产留空 `API_BASE_URL`，确认 Nginx `/api/v1/` → `:7051` |
| 登录 / CORS 403 | Origin 未放行 | 设置 `CORS_ALLOWED_ORIGINS` 含生产域名 |
| 提示配置 TokenFree Key | 未配 Key | 前端设置或 `TOKENFREE_API_KEY` |
| 视频任务失败/排队 | 方舟 Key 或模型未开通 | 检查 `ARK_API_KEY` 与 Seedance 控制台 |
| 上传失败 | 体积超限 | Nginx `client_max_body_size`、API multipart 上限（约 100MB） |
| SSE 中断 | 反代缓冲/超时 | 使用仓库 `printfilm.conf`（`proxy_buffering off`、长超时） |
